## Multi method training for facial recognition
---

This project includes the basic face recognition training and verification process. The current training process does not support distributed computing or Windows environments. The entire project is designed to adapt to the InspireFace[HyperInspire/InspireFace: InspireFace is a cross-platform face recognition SDK developed in C/C++, supporting multiple operating systems and various backend types for inference, such as CPU, GPU, and NPU.](https://github.com/HyperInspire/InspireFace), thus including the process of converting pt to mnn. Using the InspireFace model for face localization and alignment. The framework used is PyTorch. 

The training methods provided：

- traditional classification
- Feature distillation
- twin network

## Data preparation

The dataset consists of four parts in total: classification, distillation,  twin and test.  Among them, classification, distillation, and twinning are used as training. Distilled data and twin data can be the same or different. Using actual business data for testing, or evaluating with multiple types of data together. The data structures of the four parts are similar.

1. Training data partitioning usage: **split_data.py**. 

2. Classification data needs to be extracted :

```
# 1) create train.lst using follow command
python -m mxnet.tools.im2rec --list --recursive train image_folder

# 2) create train.rec and train.idx using train.lst using following command
python -m mxnet.tools.im2rec --num-thread 16 --quality 100 train image_folder
```

3. Distilling data create labels : **generate_distill_annation.py**

4. Twin data generation: **change_light.py**    Attention: The twin data generation here simulates overexposure, other methods can be customized in the file.

   Twin data create labels: **generate_ss_annation.py**  Attention: The labels for generating twin data should use the data directory before augmentation.

5. Test data label generation during training : **generate_data_pair.py**  This part of the data is used for cross-validation and is not the validation data for the classification model. Attention:  The validation data for the classification model is generated by the mxnet command.
